# Screen spec — Accounts (list, new, edit)

> Source: `apps/web/app/accounts/page.tsx` (122 lines), `apps/web/app/accounts/new/page.tsx` (165 lines), `apps/web/app/accounts/[id]/edit/page.tsx` (189 lines) — read 2026-08-05. Types: `packages/types/src/index.ts` `AccountType` (7 values: savings, current, credit_card, cash, mutual_funds, stocks, demat). Colors: `apps/web/src/colors.ts` (`ACCOUNT_COLORS`, `colorForId` — already ported for Dashboard, see `docs/mobile/screen-specs/dashboard.md`; this pass extracts it into a shared file instead of a third copy-paste).

## Scope of this pass

Ported: account list (incl. archived toggle, per-account net-worth toggle, unarchive), new-account flow for **regular accounts** (name/type/currency/color/opening balance/include-in-net-worth/allow-negative), edit-account flow (name/type/color/include/allow-negative, delete with cascade-or-keep, balance-adjustment tool). **Deferred, tracked separately:** the credit-card-specific branch of account creation (statement/due day, cycle-aware due-date preview, credit limit) — overlaps with the dedicated Credit Cards feature (web `/cards`, already its own Phase 3 task P3.9/P3.11) and is better built once alongside it, not duplicated here. Demat-specific copy ("invested" label + note) deferred with Investments (P3.10/P3.15). `MultiCurrencyCard` (accounts list's "across currencies" breakdown, only rendered for 2+ currencies) deferred — secondary, not in the primary flow.

## List (`accounts/page.tsx`)

- Header: h1 "Accounts" + right-side controls: "Show archived (N)"/"Hide archived" chip (only rendered if `archivedCount > 0`), "+ New account" button.
- Grid: `auto-fill, minmax(min(260px,100%), 1fr)`, gap 12. Each account is a `.card` with **padding 0, overflow hidden, flex row**: a 6px-wide color bar (`account.color || var(--accent)`) on the left, then a padded (18px) content column: eyebrow line `"{type} · {currency}"` (+ `" · Archived"` if archived), name (600 weight), balance (22px/700, through hide-amounts formatter), then a bottom row — archived accounts get an "Unarchive" chip; active accounts get a checkbox + "In net worth" label (toggles `include_in_net_worth` directly via SQL update, no confirmation) — and an "Edit" chip on the right that navigates to the edit screen. Archived cards render at `opacity: 0.6`. Empty state: "No accounts yet" (muted).
- Loading: skeleton cards (4, minWidth 260) while `accountsLoading || syncPending` — same avoid-the-flash pattern as Dashboard.

## New (`accounts/new/page.tsx`) — regular-account path (scope of this pass)

- Copy right under the title (not decorative, load-bearing — keep verbatim): *"Nothing here connects to your bank. You're naming a place your money sits and typing in the amount yourself."*
- Fields, in order: name (floating-label input), type (chip row, all 7 `AccountType` values, single-select, label = `type.replace("_"," ")` capitalized), currency (chip row: INR/USD/EUR/GBP/JPY/AUD/CAD/SGD/AED, single-select, default = base currency), color (row of 30px circle swatches from `ACCOUNT_COLORS`, selected = 3px border in `--text` vs 2px `--border` otherwise), "Include in net worth" checkbox (default on), "Allow negative balance" checkbox (default = `type === credit_card`, but this pass's scope is non-card so default false; still show the toggle, user can still opt in for e.g. a cash account going negative) with helper subtext that flips between an on/off explanation string, opening balance (floating currency input, only written if non-zero).
- Save: create the account (`allow_negative` = effective toggle value), then if opening balance non-zero call `setOpeningBalance`. On success, navigate to the list. Save button disabled while `name` is blank or a save is in flight; label flips to "Saving…".

## Edit (`accounts/[id]/edit/page.tsx`)

- Loads the account row by id; while unresolved shows "Loading…" (no skeleton needed, this is fast).
- Editable: name (plain input, not floating-label here — matches source), type (chip row), color (swatch row), include-in-net-worth checkbox, allow-negative checkbox (same helper subtext pattern as New). Save button disabled when name is blank.
- Row of three actions: Save changes / Cancel (back to list, discarding edits) / Delete (opens a confirm modal, right-aligned, styled `--negative`).
- Delete confirm modal: title "Delete account?" (`--negative`), body copy (from source: explains the cascade choice), two full-width buttons — "Delete everything" (cascades: soft-deletes all transactions on the account, then soft-deletes the account) and "Delete, keep transactions" (soft-deletes only the account; its transactions remain, now orphaned from an active account) — plus a Cancel chip. Both delete paths use **soft delete** (matches the golden rule: `deleted_at`, never a hard delete) — cascade path soft-deletes transactions first, then the account.
- **Balance-adjustment tool** (own `.card` section, "Adjust balance"): shows current balance (formatted), a decimal input for the target balance, two modes as chips — "Change directly" (writes a no-category `adjustment`-type transaction titled *"Account Balance Adjustment record"* — this exact string is persisted ledger text, stays English per the golden rule, do not translate/reword it) or "Record as transaction" (writes a real `income`/`expense` transaction with the same title, sign determined by whether the delta is positive or negative). Delta = target − current, in minor units; a delta of exactly 0 shows "Already at that balance" and does nothing. "Update balance" button disabled while balance hasn't loaded or the input is empty. Success shows a confirmation line with the new formatted amount.

## Shared: `colorForId` / `ACCOUNT_COLORS` (extract, don't re-copy)

Already ported once for Dashboard (byte-for-byte from `apps/web/src/colors.ts`) but inlined as private copies in `DashboardScreen.kt`/`DashboardView.swift`. This pass extracts them into a shared file per platform (`ui/AccountColors.kt`, `AccountColors.swift`) and updates Dashboard to use the shared version — per the Phase B checklist's "component reuse, no inline re-implementation" rule, which the first pass didn't fully follow.

## Data layer (verified 2026-08-05)

Both platforms' `LedgerRepository` already has everything the list/new/edit-minus-delete flow needs: `watchAccountBalances(includeArchived)`, `createAccount(...)`, `setOpeningBalance(...)`, `updateAccount(id, values)` (Android: `Map<String,Any?>`; iOS: check signature before use — matching Android's map-of-column-updates shape must be verified, not assumed), `setAccountArchived`, `deleteAccount` (soft-delete only — the account row). **New this pass:** cascade-delete of an account's transactions isn't yet a repository method on either platform (web does it inline via a raw `UPDATE transactions SET deleted_at=... WHERE account_id=...`) — add a `cascadeDeleteAccount`-equivalent, or inline the same raw update, matching web exactly (transactions first, then the account, both soft-deletes). The balance-adjustment tool's two write paths both go through the existing `createTransaction` (Android)/equivalent (iOS) — verify iOS has a matching one-shot create before assuming.
